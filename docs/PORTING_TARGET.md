# 1.12 → 1.20.1 移植目标

本移植以 `Pollution` 上游 `098834e`（2026-08-30，GTQT/Pollution）为基线，配合上游最近的地下世界、无线星流和轮机提交检查 Git 历史；目标是把玩家可见的机器、配方、污染系统、Warp 表现、结构战利品、JEI 信息和网络 API 移到 Forge 47.4.23 / Minecraft 1.20.1。

## 已纳入

- 源质魔导轮机 LV/MV/HV，以及使用 `MANA_TO_EU` 的大型魔力轮机；结构、转子耐久、燃料配方和 JEI 文案保持现代 GTCEu 语义。
- 星流的 16 个星座通道、枢纽核心、中继、跨维网关、操作核心、区块锚、绑定器和原子多通道扣款 API。中继只路由已加载的目标，区块锚使用 Forge 强制加载。
- Warp 事件的独立配置开关、假雨客户端粒子、无伤假爆炸、可靠 Blink、倒计时炸弹队列和管理员诊断指令。
- 上游 GT 材料/蒸汽机器/credits 战利品到现代结构的等价注入，以及四页魔法 JEI 指南的说明型页面。
- 矿物提取器物品 BEWLR、Curios 护目镜/翅膀模型和原版史莱姆外胶层。

## 明确边界

血魔法和星辉魔法（Astral Sorcery）仍按移植范围排除。星流网络本身是独立系统，但上游星座塔供能端依赖 Astral；本版本提供 `receiveConstellationEnergy` 供兼容整合调用，不伪造独立的生存供能闭环。晶圆、塔罗和相关 JEI 页面保留为数据说明，页面会标出该依赖。

上游 TESR 中依赖被排除模组的动态模型、原版没有对应方块的血肉丘，以及 Betweenlands 专有战利品表不会强制加载外部模组。缺失的外部命名空间只会跳过注入，避免污染无关存档。

星流枢纽在 1.20.1 使用可放置的核心方块承载网络状态；上游 29×33 方尖碑多方块和动态 TESR 属于表现层缩减，不影响容量、路由、绑定和原子扣款接口。

## 验收标准

`compileJava`、资源 JSON 检查、数据生成、Forge GameTest 和无图形服务器烟测必须通过；烟测重点覆盖注册表、轮机结构/燃料、Warp 假表现不改天气、污染地形阈值和星流网络保存/路由。任何依赖 Astral 的功能必须在日志或 JEI 中明确显示为范围外依赖。
