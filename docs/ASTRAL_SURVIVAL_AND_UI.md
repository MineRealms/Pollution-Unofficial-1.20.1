# 星辉生存配方与多方块界面

更新日期：2026-09-27。对照本地 Pollution 1.12 上游、Astral Sorcery 1.20.1.0 和 GTM 7.5.3。

## 玩家可见变化

- 补齐五台星辉处理机、十六座星座塔、两级透镜仓的中文名称及五个 JEI 配方分类标题。状态界面不再混用硬编码英文。
- 五台处理机采用上游星辉大理石砖底纹和 GT HPCA 正面。成型仓室使用控制器指定外壳，保留能源、魔力、塔罗、透镜等仓室图标；拆解后恢复独立仓室底纹。
- 55 套已有连接纹理从旧 CTM 描述转换为 GTM 所用的 LDLib 格式，不需要额外安装 CTM 模组。
- 魔法机器使用 GTM 状态面板和仓室页签；标题、提示可换行。新增星座页签，按原生星座点线绘制，显示天空、光学品质、塔罗与加工增幅。上游该面板由代码绘制，没有整张 GUI PNG。
- 无普通物品配方界面的节点、储能、星座塔等控制器继续显示状态信息，不添加无意义的输入输出槽。
- 工业注魔池的物品提示及未成型界面会提醒补满中心注魔器周围的 24 格液态星辉。GT 终端不能自动放液体。

## 生存路线

1. 按 Astral 原生流程取得、调谐岩石水晶。切割调谐水晶可获得调谐晶圆，作为工业链的前置材料。
2. 制作共振线圈、基础/高级透镜和空白校准核心，再制作 MV 或 LuV 透镜仓。空白数据晶圆用于高级仓的制造，不能提供星座授权。
3. 观测阵列使用对应星座纸、调谐晶圆和数据棒，在满足天象要求时产出带星座的数据晶圆。
4. 魔导组装机把原生岩石水晶制成晶种，再制成胚胎；生长阵列按目标星座培育。产物保留源晶体和代数、原生晶体属性及光学品质。
5. 校准要求对应星座晶圆和光学品质至少 70% 的培育晶体。JEI 显示所需星座、夜间、分布门槛及属性继承规则。
6. 五台控制器和两级仓室有独立制造配方；十六座星座塔使用各自的带星座晶圆制造，避免相同配方只能获得其中一种塔。

工业注魔器及工业集光井导入当前数据包中的原生 Astral 配方；本地 Astral 提供 26 条注魔和 11 条集光。集光催化剂不消耗。原生要求复制输入属性的注魔配方保留真实输入 NBT。

## 实现与兼容

- 输入属性在 GT 计算并行和模拟输出空间之前写入配方副本。消耗原料严格绑定到被选择晶体的 NBT，避免混合品质输入复制出同一品质。
- 动态输出使用 GT 标准配方序列化，随进行中的配方保存，不在完成后补写物品。
- GT 生成模型保留在 `block/machine/`，手写基础模型迁至 `block/machine/base/`，避免资源重名遮蔽 GT 换纹理元数据或形成循环引用。
- 186 种仓室模型声明可替换纹理，72 个控制器模型声明外壳纹理；`appearanceBlock` 提供成型后的连接判断。
- 生长阵列的五格核心使用可合成的魔法夹层玻璃。Astral 1.20 的 `translucent_block` 是没有物品的内部临时方块，不能用于生存搭建。
- 生长配方需要额外放一片对应星座的数据晶圆作为不消耗模板，以便 GT 的配方索引区分十六个星座；透镜仓仍需对应晶圆。
- 上游胚胎制备在当前端使用魔导组装机，保留魔法资源成本。
- 海水提溴兼容 GTM 的固态碘：没有液态碘时，用 1% 概率的一份碘粉保留微量副产物，避免整条配方被跳过。
- JEI 对齐 Astral 端使用的 15.62.0.216。DEV 原来的 15.56.0.205 缺少星辉配方转移需要的 `IRecipeTransferContext`；旧 JAR 已备份后替换。

## 验证

资源检查命令：`python tools/audit_machine_resources.py`。检查模型引用、GT 包装模型是否被覆盖、仓室换纹理字段、连接纹理目标和中英文键覆盖。

服务端检查：`gradlew runGameTestServer`，43/43 项通过。1277 条已加载的 Pollution/原生代理配方通过原料、数量与槽位检查；原生配方覆盖及各机器/星座配方通过 GT 索引检索。新增逐 tick 测试通过注册的机器修饰器和 GT 输入输出流程验证：注魔保留真实输入 NBT、堵输出不扣料、集光催化剂不消耗、晶种→胚胎→培育完整加工保留源属性。天象与外部魔法供应在此类测试中由夹具提供，不能作为全部天空条件的实测。

111 张涉及本次连接纹理和透镜仓的 PNG 均通过上游 SHA-256 对比。1361 个模型引用检查通过，无循环引用或手写模型遮蔽 GT 包装模型；1246 个生成英文键均有中文。

DEV 客户端 Rosetta 语言查询确认 3411 个 Pollution 注册物品均无裸 key，五个星辉配方分类显示中文。渲染线程调用实际 GT `MachineModel.replacePartBaseModel` 确认能源、魔力、灵气、塔罗及透镜仓的电压外壳纹理被替换为原生大理石砖，仓室图标保留；该探针用控制器代理隔离成型条件，不改玩家结构。正常 GT UI 工厂打开临时注魔器并截图确认中文状态和池面提示换行；临时方块已恢复。JEI 升级后原生星辉配方转移注册成功。

星座页签另以临时控制器和真实 LuV 透镜实例加载御虚座晶圆，服务端正常同步后截图确认原生星图、中文名称、天象状态与增幅行显示正常；页签隐藏无关的背包区域以适应小窗口。测试结束后恢复临时方块及失焦暂停设置。

当前星座塔保留本端的 5×7×5 星流外壳结构及 Starstream 供能方式，未改成上游 8×13×8 仪式塔；上游北斗仪式增幅也不能据本轮 UI/配方测试视为已实现。所有天气/月相组合及完整从零生存通关不属于自动测试已经证明的范围。
