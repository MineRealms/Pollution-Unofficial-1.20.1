# Astral Sorcery Rosetta 实机验证

日期：2026-09-27。

测试对象为 Sunlit Valley **DEV** 客户端当前单人世界的集成服务端：
`G:\MinecraftGames\Sunlit Valley(BaopuEdition)-DEV\.minecraft\versions\Society Sunlit Valley`。
客户端已安装 `rosetta_remote_debug_bridge-1.0.0.jar`，通过本机桥接在 `Server thread`
执行探针。没有使用独立 Gradle 客户端代替整合包实测。

## 通过的项目

| 项目 | 观察到的结果 |
|---|---|
| MV / LuV 透镜仓 | 分别为 1 / 2 格；接受原生星座纸和带星座 NBT 的晶片；拒绝空白晶片；锁定时不能取出；保存数据包含星座与锁状态 |
| 透镜增幅计算 | 测试天空条件下，Vicio 晶片得到 9% 传输增幅，Armara 晶片得到 9% 容量增幅；这是实际仓室的计算结果，未测完整电池的最终容量 |
| 五类星辉处理机 | 用各自结构预览搭建，五台控制器均成功成型 |
| 工业集光井 | 自动处理投入的线圈，实际输出 1000 mB 液态星辉 |
| 工业星辉注魔器 | 补全流体标签并重载后，消耗基础透镜、线圈及液态星辉，实际输出 1 个高级透镜 |
| Aevitas 星座塔 | 成型、自然产能并向绑定的 Starstream 核心输送；核心储能实际增加 |
| 天空遮挡 | 塔顶遮挡后 generation 为 0，解除绑定后的塔内能量维持 1308，不再增加 |

测试使用远离玩家建筑的空中区域；提供配方原料和持续 EU 以隔离供电因素，
由机器正常 tick 完成上述两条加工。没有改动玩家背包或世界时间。
测试结束后已恢复 2161 个空中方块位置（残留非空气方块为 0），取消供电回调，释放 12 个测试区块票据。
原始探针和结果位于本地忽略目录 `build/rosetta-astral/`，不包含连接凭据。

## 本次修复

新增 `data/forge/tags/fluids/liquid_starlight.json`，把 Astral 的源流体和流动流体
加入 `forge:liquid_starlight`。两个注册项均标记为可选，不安装 Astral 时不产生缺失条目错误。
修复前，注魔器虽然通过完整配方匹配，但流体标签未进入 GT 配方查询索引，机器保持空闲；
修复后正常查找到配方并产出高级透镜。`reobfJar` 构建通过。

当前 DEV 世界已通过 `pollution_astral_starlight_hotfix` 数据包加载同一标签，修复即时生效。
新构建 JAR 也包含此标签；正在运行的客户端 JAR 未被热替换。安装新 JAR 后该数据包可移除。

## 尚未完成

- 观测阵列、晶体校准器、晶体生长室的配方输出没有星座/晶体属性 NBT；已验证结构和配方注册，
  不能将它们记为完整加工通过。对应逻辑需要接入星座晶片、晶体胚胎和培养晶体的 NBT helper。
- MV / LuV 透镜仓缺少生存制造配方，目前只能通过创造模式或命令取得。
- 未覆盖所有星座塔、所有天气/月相、服务器重启后的恢复和完整生存流程。

因此，星辉联动的基础运行已实测，但与 1.12 上游的完整玩法对齐仍未完成。
